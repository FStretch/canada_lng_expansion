# Publication audit

Written 3 September 2026 against commit `d3c84df`. **Nothing was changed.** One full
`python build_results.py` was run to test reproducibility; the three files it touched were
restored with `git checkout` and the tree is clean.

Every one of the 115 tracked files is classified below. Totals:

| group | files | size |
|---|---:|---:|
| Keep, load-bearing | 74 | 2.1 MB |
| Keep, robustness | 30 | 4.1 MB |
| Retire | 6 | 1.0 MB |
| Uncertain | 5 | 3.9 MB |
| **total** | **115** | **11.2 MB** |

The retire list is small and unglamorous. That is the honest finding: this repository is in
better shape than the brief assumed. There is no earlier figure set, no earlier results
workbook, no abandoned branch of code. What there *is* — and the brief did not anticipate it —
is **four documents whose own "current values" banners have gone stale**, which is a worse
problem than clutter, because a banner that says "current" and is not gets read as fact.
Section 5.

## 1. Keep, load-bearing

**The model — 17 files, 216 KB.** `build_results.py` and `src/*.py`. Every module in `src/` is
imported by `build_results.py`; there are no unreachable modules. `inputs.py` is imported by
all 14 others, `scope.py` by 12, `model.py` by 11, `trajectories.py` by 10. `src/__init__.py`
re-exports from `model.py`.

`eccc_sc_co2.csv` and `eccc_sc_ch4.csv` (the published central case, both gases),
`burke_horizons.csv` (Figure 2e horizons), and in `loss_damage_r1/`,
`total_damages_by_pulse_2100.csv` (`burke_pulse_file`),
`burke_country_damage_shares.csv` (`burke_country_shares_file`, source of the 0.1704% Canada
share the run asserts) and `burke_fig4_canada.csv` (`burke_fig4_canada_file`).

**Published outputs — 45 files, 1.6 MB.** `Canada_LNG_Emissions_Results.xlsx` (24 sheets),
`RESULTS_SUMMARY.md`, `paper_set_locked.csv` (its SHA-256 is asserted every run),
`si_table_assets.csv`, `benchmark_comparison.csv`, the nine numbered figures `fig01`–`fig06`
and `fig08`–`fig10`, and the 32 CSV series under `figure_data/` that back them. Every one of
these was rewritten by the verification run (section 6), so none is an orphan from an earlier
state of the model.

**Repository furniture — 4 files.** `README.md`, `requirements.txt` (exact pins, because the
SHA-256 lock would fail on a float-formatting change), `CITATION.cff`, `.gitignore`.

## 4. Uncertain — 5 files, 3.9 MB

### `Outputs/figure_data/mc_draws.csv` — 3.9 MB, current output, and the reason the repository is heavy

10,000 raw Monte Carlo draws, rewritten every run. It is a current, live output, so it does not
belong on the retire list. But it is the single largest file in the repository, it is 35% of the
whole tracked tree, and being fully determined by `monte_carlo_seed` it is reproducible in
seconds by anyone who clones. Every re-lock commits another 4 MB copy: it and `SLIDE_TABLES.xlsx`
are the twelve largest blobs in the entire history, between them.

**My recommendation is to keep it.** A reader who wants to check the published interval without
installing anything can open the draws, and the summary and parameters CSVs alongside it are not
a substitute. Flagged so you can overrule, not because I think it should go.

### `Inputs/loss_damage/cboc_rising_tide.csv` — 1.3 KB, protected

Conference Board *A Rising Tide* denominators for the dropped economic-value analysis. No script
reads it; its values are duplicated into `parameters.csv` as the `cboc_*` rows. It reads as an
orphan. **It is not one** — your standing ground rule is that the dropped economic-value analysis
is labelled, not deleted. Listed so the classification is complete, not because I am asking.

### `Outputs/SCOPE_DIAGNOSTIC.md` — 5.3 KB

The legacy and non-export asset diagnostic from the all-assets scope, 29 August. Its content is
superseded and it carries a banner saying so — but the banner's own "current" values are three
locks out of date (section 5). Either fix the banner or retire the file. It is the only dated
document whose analysis bears on nothing now published.

### `Outputs/OIL_COMPARATOR_AUDIT.md` — 17.8 KB

**I disagree with retiring this one**, and it is worth being explicit because the brief named the
oil comparator as the clear case. This document is not the retired analysis. It is the *audit
that established the comparator was unsound* — that `tmx_expansion_bpd` had no URL, that the
Alberta–BC bitumen bar was an unvalidated first pass, that the whole thing lived in Python
defaults rather than in the workbook. Figure 7 was retired **because of** this document.
Deleting it removes the justification for a deletion and leaves the change reports asserting a
conclusion whose working is gone. Keep it, and add a banner saying the analysis it audits is
retired.

### `Outputs/LCA_ROMAN_WHITE_GAP.md` — 7.9 KB

The Roman-White 2021 gap diagnostic, 28 August. Still live evidence — the aligned
well-to-regasification comparison is a robustness check the paper leans on. But it states the
model at **0.80 tCO2e/t** well-to-regasification where the current run produces **0.76**, and
unlike the other dated documents it carries **no superseded banner at all**. Keep, but it needs
one. Section 5.

## 5. Check one: superseded outputs a reader could mistake for current

**There are no duplicate output files.** One results workbook, one slide workbook, one figure
set, one summary. The failure mode the brief was most worried about does not exist here.

The real problem is different and, I think, worse. **Four documents state "current" values that
are not current.** A reader who trusts a banner is misled more directly than one who finds two
files and has to choose.

| file | states as current | actually current | out by |
|---|---|---|---|
| `Outputs/SCOPE_DIAGNOSTIC.md` | 9,298.1 Mt, 298.2 Mt peak, 18.1 / 3.2 / 78.7 | 7,162.0 Mt, 235.6 Mt, 17.6 / 3.2 / 79.2 | three locks, pre-Discovery |
| `Outputs/SOURCING_AUDIT.md` | 7,254.2 Mt, 238.6 Mt, C$3,143 bn | 7,162.0 Mt, 235.6 Mt, C$3,108 bn | one lock |
| `Outputs/DECK_RECONCILIATION.md` | 7,254.2 Mt, 238.6 Mt, C$3,143 bn | as above | one lock |
| `Outputs/LCA_ROMAN_WHITE_GAP.md` | 0.80 tCO2e/t well-to-regas — **no banner at all** | 0.76 | one lock, and undeclared |
| `CITATION.cff` | `version: 2026.08`, `date-released: 2026-08-29` | four rounds of changes since | four commits |

**Why `tools/stale_figure_inventory.py` reports 0 live hits and misses all of this.**
`SCOPE_DIAGNOSTIC.md`, `SOURCING_AUDIT.md` and `DECK_RECONCILIATION.md` are on the whole-file
`ALLOWED` set, so *every* superseded value in them is exempted — including the ones inside a
banner claiming to be current. `LCA_ROMAN_WHITE_GAP.md` is not exempted, but 0.80 is not one of
the `SUPERSEDED` patterns, so nothing looks for it. `CITATION.cff` is not scanned at all.

The exemptions were right when they were written: those files legitimately quote old numbers in
their bodies. But a whole-file exemption cannot tell a quoted historical value from a claim about
the present. The fix is to make the banners generated rather than hand-written — the same lesson
the inventory already records about having gone stale twice itself.

Recommendation, for a later commit and not part of the retire list: give each dated document a
banner produced from `EXPECTED_BUILD_OUT`, and assert that a banner matches the current lock.
That turns five hand-maintained claims into one generated one.

## 6. Check two: does every script run, and is every output used

**Every script compiles.** `python -m py_compile` over all 31 Python files: clean.

**The run reproduces exactly.** `python build_results.py` exits 0, prints 42 passing assertions
and ends "No input file was modified during the run." Comparing the working tree to `HEAD`
afterwards, **only three files differed and only by a timestamp**: `RESULTS_SUMMARY.md` (two
lines, the run clock) and the two output workbooks (embedded creation time). Every figure, every
CSV series, `paper_set_locked.csv`, `si_table_assets.csv` and `benchmark_comparison.csv` came
back byte-for-byte identical to what is committed.

That is a stronger result than the brief asked for. It means the committed outputs are the
outputs of the committed code and inputs, with nothing hand-edited and nothing left behind.

**Every output is consumed, with one exception.** The run's own writes touched all 32
`figure_data/` CSVs and all 10 PNGs, so there are no leftovers from an earlier figure set. The
exception is `operating_vs_proposed.png`, produced but referenced nowhere (section 3).

**The 15 `tools/` scripts were not re-run**, deliberately: they write to `Inputs/`, and the run
asserts the inputs are unmodified. They are one-off and already applied — each records a single
workbook edit with its old value, new value and source. `stale_figure_inventory.py` is the one
exception, meant to be re-run after every re-lock, and it was: 0 live hits, with the blind spot
described in section 5.

## 7. Check three: does the README match the repository

Mostly. The structure block is accurate for what it lists, and the module one-liners are right.
**Nine tracked files are missing from it**, of which two matter:

| missing | why it matters |
|---|---|

| `CITATION.cff`, `requirements.txt` | In the repository root, absent from the tree. |

**There is no "start here".** The README opens with what the model produces, which is right, but
a reader landing on a public repository of 115 files has no pointer to the four or five that
matter. Suggested, for the post-sign-off commit:

> Start with `README.md`, then `Outputs/RESULTS_SUMMARY.md` for the numbers,
> `Inputs/Canada_LNG_Data_Inputs.xlsx` for every factor and its source, `build_results.py` for
> what is asserted, and `Outputs/SOURCING_AUDIT.md` for the verdict on each number's provenance.

The tree should be regenerated after the retire list is signed off, not before.

## 8. One item outside the four groups: git object hygiene

`.git` is **88 MB on disk** against a **5.1 MB pack** — 562 loose objects holding roughly 80 MB,
almost all of it repeated 4 MB copies of `mc_draws.csv` and 3 MB copies of `SLIDE_TABLES.xlsx`
from successive re-locks.

This does not affect anyone who clones the repository, since a clone transfers the pack. It is
local hygiene only. `git gc` before publishing collapses it and rewrites no history. Noted for
completeness; not a task.
